可行性与查新

可以开始做小规模验证。最值得押注的是“准备动作的配对证据能否帮助系统学会挑选下一轮实验”。 按需想象、失败回溯、主动采集和按学习进度选课程，都已有接近的工作。这里把这些部件分开测量，并用等预算的新学生实验检验选择器本身的改进。

目前测到了什么

在现有容器中，用 RTX 4090 D、原版 LIBERO-Goal 任务索引 3（打开上层抽屉并把碗放进去）与 π0.5 checkpoint 实测。初始状态索引 0 的一条基线 rollout 在 settle 之后第 199 步成功。模型返回 10 × 7 动作段，在线按 5 步执行。当前机器人状态实测是 8 维，由末端位置、轴角和两维夹爪关节位置拼接。该次 rollout 的预热后策略 RPC 中位数约 78 ms，作为本机估算参考。

在同一任务的五个官方初始状态（索引 0–4，仿真种子 7）分别保存前 5 步策略命令。重置并重放这段命令后，同一状态的 agentview 图像逐像素一致。相同候选执行两次，5 步扁平仿真状态的最大绝对差都是 0。改用等长保持对照，末端位置与候选相差 4.33–4.61 cm。这验证了本机可以通过确定性前缀回放构造分支对照。直接恢复中途快照和跨任务重放仍需单独验收。

目前尚无世界模型排序、干预成功率或 RSI 的实测结果。 Prophet 的 LIBERO 权重公开，但运行所需的 NVIDIA tokenizer 匿名请求返回 HTTP 401。需要已有 Hugging Face 访问权限和独立运行环境。其公开接口固定 20 步、单视角；短时间接触和候选尾序列引起的排序偏差，必须用实跑分支检查。 Prophet 模型卡 · Cosmos 依赖

三个决定是否继续的实验

  1. 先测干预上限。 用 30 个独立快照测可执行候选相对等长重试的配对收益，同时包含正常状态和无解状态。按预先固定的规则选出候选，再用独立回放种子估计其收益，避免同一批回放既选最佳又报最佳。若上限很低，优先改善任务和候选库。
  2. 再测想象有没有额外价值。 用真实未来图像的打分器作为观察上限，和 action-only、Prophet 三者共享候选。如果真实未来图像也无法区分有效动作，先改视角、事件定义或预测视界。如果上限高而 Prophet 追不上，借鉴 ForkCast 的短视界 latent 预测，使用本地分支数据训练。
  3. 最后测改进器是否在学。 先复用一批已验证数据，隔离“选样本”的效果，用三种简单配方比较开发集收益方差。只有配对收益稳定后，才在线让选择器改变采集，并检验它是否强于学习进度采样。如果只有学生表现提高，结论限于数据采集或策略改进。

平台选择

主实验采用 LIBERO 的独立干预扩展，RoboCasa365 做跨平台复验。 第一阶段优先考虑能否重放干预、能否独立下载动作条件 WM、与现有 VLA 是否兼容，以及成对分支的采集成本。原版 LIBERO 用来测接口与退化，研究效果在有准备动作需求的扩展场景上验证。

第一批任务与成对标签

先做“抓取入口被可移动物体挡住”。从基础策略失败快照比较直接重试、改接近方向、先移走阻挡，再交回相同、冻结的抓取 skill。做无阻挡场景和没有有效干预的场景，检查 controller 能否略过无用的想象或停止。再加入“遮挡需换视角”与“抓取姿态需先调整”两个机制。候选先测独立可执行率，然后以留出的物体、布局和技能组合测新组合。报告以候选库为范围的能力发现，另记录新组合是否由 learned proposer 主动提出。

保存并验证模拟器、控制器、任务计数、历史和 RNG 状态。对每个快照配对候选与 retry，另设等长 hold，重复使用相同 seed 集和 skill 时限。比较 Δenable = P(success | prep) − P(success | retry)，成本独立记录。对照环境标签先用分支后实际状态与后续 skill 的成功，不从 WM 生成画面写入 ground truth。

自采与开源的最小交付

  1. 用独立 BDDL 场景和参数配置生成布局族。以抓碗为例，设置无阻挡、可移开阻挡和无法移开的阻挡三类。保存目标物、阻挡物、初始位姿和相机配置。按布局族、物体与机制划分 train、dev 和封存 test，再生成具体快照。
  2. 固定基线模型和触发规则采集 rollout。以两个重规划点没有目标进展、抓取失败或首次碰撞作为候选快照来源，同时从正常轨迹抽样。每个快照回放默认重试、等长保持、退回后接近、换侧接近或推开阻挡等适用动作。每条回放先执行准备前缀，再交给同一冻结技能。保存不可达、超时和无效果记录。教师脚本若用仿真物体坐标，只在训练数据生成和 oracle 对照使用。部署候选从可见观测和模型输出生成。
  3. 保存环境版本、BDDL 与资产 ID、初始快照、仿真控制步长、相机标定、每步 env 动作及时间戳、双视角帧、机器人状态、接触事件、技能成功、分支父子 ID、候选来源和成本。训练侧输出 LeRobot 示例轨迹、Parquet 分支索引和按 episode 分片的 MP4。快照用 NPZ 加 JSON 元数据记录，提供从初始种子和原始动作回放的途径。
  4. 拟发布到独立 Hugging Face Dataset，配套数据卡、场景生成与回放脚本、固定 train/dev/test 清单、资产许可和校验清单。公开同状态的失败和对照，方便复现排序与触发实验。第三方示范默认只记录来源与 ID，由复现者自行获取。用于盲测的种子可在实验锁定后释放。

详细实验协议

实验 A · 准备动作有没有因果收益

定义主任务为抓取并放置目标物。冻结后续抓取技能与最大步数。令 S(h,u,k,s) 表示从快照 h、随机种子 s 执行准备动作 u 后，同一技能 k 是否成功。对每个 h 使用同一组种子分别评估 prep、retry 和 hold。报告配对差 mean[S(prep) − S(retry)]、prep 对 hold 的差、任务最终成功率及新增动作步数。若仿真与控制完全确定，重复同一条件只做重放检验，统计样本来自独立布局或状态族。

对一个抓取受阻场景先做 30 个快照。先重放同一动作并核对 EEF 轨迹、关键接触、成功标签及终止步数。预试可以用 20 步的准备动作验证机制确实存在。进入 5 步主实验前，再检查候选 oracle 在 5 步前缀下有足够的区分度。若干预无法在 5 步产生可测效果，设独立的 20 步方案，所有对照共用该周期，按实际动作步数计费。

实验 B · WM 会不会按动作改变判断

在同一快照生成同一组候选，记录实际分支的关键事件，例如阻挡物是否离开抓取区域，以及后续技能成功。用真实观察训练 effect head。用独立开发快照校准 WM 预测输入。固定相同候选与计算预算，在封存快照上对比真实未来画面上限、WM、同容量 action-only head、复制起始帧和打乱动作的 WM。主指标是非平局配对排序与选中候选的真实 regret。实际收益并列的候选对单列。对其余候选对，模型预测并列计半分。统计按任务与快照聚类。另列接触和物体运动的逐事件准确率、Brier 分数及更换 15 步尾序列后的排序稳定性。

实验 C · 什么时候值得分支

部署从完整 episode 起点运行，不能跳到已知失败状态。各组共用候选生成器、执行周期和任务上限。固定频率与随机触发先在 dev 匹配可用的 WM calls/episode，按候选预测次数计费。封存测试分别报告实际消耗和不同预算下的成功率曲线。每个初始状态和种子同时测直接执行、固定频率、随机触发、学习触发与仅用 action-only 打分，另用全点想象描出成本上界。增加同预算的候选优势门控和廉价置信度门控，检查学习触发器是否优于接近的已有做法。按训练资源、基础动作候选生成调用和 WM 推理分开报告 GPU 时间。主对照为学习触发对等预算固定频率。

实验 D · 学到了技能，还是只靠推理时搜索

对比同一 π0.5 起点上的原策略、仅 SFT、SFT + 环境 RL、以及只在推理时使用 controller。SFT 各组使用相同数量的训练动作和优化步数，对比分支排序选出的正例与随机抽样正例。RL 组从同一 SFT 起点出发，在相同训练环境步数下对比有无分支初始化课程。评测时各权重组关闭 WM 和外层控制器，以单次策略调用执行，另报告完整系统成绩。扩展场景和原版 LIBERO 分开计分。

启动预算建议为 120 个快照、每个最多四条主分支和三组可用种子，约 1,440 次分支，等长 hold 另计。确认性实验按 dev 的配对差、方差与任务内相关性估算样本量，提前锁定主指标。跨任务样本较少时逐任务报告，并把区间和结论限定在实际任务族。

强化学习流程

训练顺序是示范预热 → 触发器 RL → 连续动作 RL → 外层实验选择 RL。 各层在自己的时间尺度使用环境证据。首轮先冻结 π0.5 验证想象与触发效果。通过 G2 后再动策略权重，才能归因增益来自哪一层。

层策略与动作环境奖励与更新
预热π0.5 action expert，学习通过验证的完整动作段Flow matching SFT，先混合验证轨迹与原始示范，例如 1:1。失败分支用于打分和触发标签。窗口用实际执行轨迹构造，边界 mask 掉补齐步。

怎样执行π0.5 action expert，以连续动作段控制机器人真实仿真成功加可选的事件奖励。使用 RLinf 的 Flow-SDE PPO 更新，独立价值头估计回报。

阶段一 · 触发器的离散 RL

  1. 为每个决策记录实际观测历史、技能进度、剩余预算、旧策略的 action 概率及候选生成成本。由同状态下 DIRECT 和固定 WM 选择结果的真实分支获得 Δgate = return(imagine) − return(direct)。用它预训练门控分数，按 dev 的成本曲线选阈值。
  2. 第一版可用每回合只在一个符合条件的决策点随机化，后续用同一冻结策略完成任务。记录已知采样概率，用 bandit 更新该决策。多个决策点互相影响时，改用完整 episode 的离散 PPO。每次迭代先用旧 gate 采一批完整轨迹，然后按真实 rollout 计算优势和价值目标，再更新 gate。
  3. 可执行的初始奖励定义为 r = 1[首次完成任务] − λwm·WM_calls − λt·extra_seconds − λbad·1[硬失败事件]。系数在 dev 按调用和时延约束确定，训练时可加经消融验证的阶段事件。主评估继续用原始成功率和实际成本。终止、超时与 padding 分开记账，重规划点间按实际经过步数累计回报。

阶段二 · π0.5 连续动作 RL

  1. 先在 RLinf 官方 LIBERO 配方验证训练和评估，再接独立扩展环境。官方配方使用可训练的 RLinf/RLinf-Pi05-LIBERO-SFT。若采用它，所有策略训练对照从同一 checkpoint 起步，并重跑基线。现有 OpenPI websocket 服务用于原版推理基线。迁移其权重到其他训练框架时，先验证动作归一化及相同输入下的输出一致性。
  2. 从同一 SFT checkpoint 初始化 actor 与 critic，固定本轮 rollout actor 版本。每个重规划点从 Flow-SDE 随机去噪采样，存去噪轨迹、旧 log-prob、价值估计、动作维度和有效时间掩码。pi05_libero 的模型动作视界为 10，主实验只执行 5 步。由环境返回每步奖励、首次成功、超时与结束观测。每轮按 RLinf 实现重算相同去噪随机变量的 log-prob，使用一致的截断、掩码和归一化。
  3. 把有效步奖励聚合到动作段，用 GAE 估计优势，再优化 PPO clipped ratio 与价值损失。可从 γ=0.99、GAE λ=0.95、clip=0.2 起步，在 dev 调整，记录 KL、clip fraction、价值误差、动作越界和每批成功率。先只训练 action expert 和 value head。SFT 保持项如要加入，用独立示范批计算并做消融。每轮上线采新数据。固定的离线成功分支用于 SFT 和课程起点。
  4. 第一轮 RL 用真实仿真奖励，WM 在冻结条件下提出候选、决定哪些状态值得补采。用于 actor PPO 的连续动作由本轮 actor 自己采样。若 gate 改写或筛选了动作，该步标为 teacher，进入单独的蒸馏数据流。这样 PPO 的采样策略和 log-prob 定义能对应。后续若做 WM 内 rollout，另设等仿真预算对照、真实验证与模型偏差门槛，单独报告。

阶段三 · 外层实验选择 RL

每次选择一个可审计的实验批次。例如，从失败状态、模型分歧状态或随机状态各抽一组，按策略分配名额。为每个动作保留已知探索概率。由同一学生 checkpoint 克隆实验组与固定采样组，匹配验证步数、训练样本量、优化步数、optimizer 起点和随机种子。各自完成一轮等步数更新，再从相同 dev 起点量学生性能差，扣除额外算力成本。以这项批次回报更新选择器。第一版每批只选一种配方，避免把批级收益错误分给单条轨迹。记录回报方差、动作概率和随机探索覆盖。下一轮由更新过的选择器重新决定采什么，再做新学生移植与递归一跳对照。

G0 · 可重放、候选可用30 组快照重复回放同命令，检查终点、事件与成功标签。评估无阻碍时原 skill、受阻时 retry，以及候选 oracle 上限。成对标签可重现，oracle 对 retry 有正收益。否则先修快照、候选或基础技能。

G2 · 知道何时想同 K、相同候选、相同 evaluator、同一执行前缀。对照直接 π0.5、同候选 action-only、固定频率、随机触发、每点想象、oracle。每点想象另报成本曲线。与预先指定的固定频率对照比，于匹配 WM 调用上限有正的配对成功率差。同步报告 P50/P95 延迟、误触发及有益分支漏判。
G3 · 策略学会干预以环境验证轨迹训练 π0.5 adapter，混合原示范。对照等量随机、固定难例与同数据量无成对排序。评估时关闭 WM、使用单次策略调用。新组合上成功率增益为正，原版 suite 退化在预先指定容忍范围内。把带 controller 的系统收益另列。
G4 · 改进器学会改进相同新学生起点替换早期／后期选择器。比较等预算学习曲线、AUC、达标环境步数及下轮更新收益。后期选择器的 AUC 差 95% CI 下界 >0，并有下一轮反馈优于冻结或打乱反馈的证据。分开报告学生进步与递归证据。

验证改进器本身变强

  1. 选实验。 第 r 轮在同一训练快照池，以选择器 φᵣ 分配候选验证与数据比例。固定规则／随机探索用相同验证预算。保留探索配额，覆盖预测器没有信心的场景。
  2. 测量学习增益。 将同一 θᵣ 的 adapter、optimizer 起点及更新步数复制到实验组与对照组。用各自收集的真实数据更新 K 步。保持 WM、effect head 与 evaluator 一致，记录 Rlearn = Jdev(θselected) − Jdev(θcontrol) − λ·额外成本。开发集只提供外层反馈。
  3. 用收益更新选择器。 第一版用小型 contextual bandit，记录探索概率及每批数据的 Rlearn，更新哪些状态、干预和难度值得验证。执行 gate 由 G2 的决策收益监督。保存 φ₀、φ₁、φ₂ 等 checkpoint 及产生各版的数据路径。
  4. 做新学生移植。 至少比较三个更新轮、三个独立种子作起点。把 φ₀、φᵣ、冻结规则、学习进度采样与打乱反馈版本各自接到同一全新 θ₀、WM、effect head 和相同初始记忆。在未见任务的 adaptation starts 内用等量预算收数据，在另一批封存的 evaluation starts 测量学习曲线。禁止用封存评测分数更新任一版本或调阈值。
  5. 检查递归一跳。 让早期与后期选择器各产生一批等量的下一轮实验，采用相同 meta-update 规则更新各自的副本，测各自更新前后对另一批新学生的边际教学增益。冻结选择器与等量、打乱的 meta 反馈是对照。若只有 G3 通过，结果支持策略自改进。若移植通过而递归一跳未通过，结果支持改进器学习，递归仍待证。

开工顺序与交付证据

  1. 资产与 baseline。 在仓库外建 WM runtime，验 SHA、跑 demo 原动作／替换动作、记录单卡显存及延迟。用既有 π0.5 server 跑原版 smoke，确认 180° 翻转、224 pad resize、8 维 state、10 步 settle、suite step cap 及 5 步重规划。官方结果与自建任务分表。
  2. 干预数据与 shadow mode。 建一个阻挡场景，做快照回放验收。记录同一状态所有候选的预测与真实对照，先离线给分支排序。保存 snapshot_id、任务／分割、候选命令、模型版本、帧对齐、事件、决策、Δenable 与成本。输出 G0／G1 报告及失败样本。
  3. 闭环消融。 G1 通过才在独立实验 runner 接 controller；接入点是 action queue 补充前的重规划边界。WM timeout、低置信度与预算用尽均记录回退原因。以相同 seeds 完成 G2 对照，再做 G3 adapter 蒸馏。
  4. 改进器验证。 G3 通过后跑外层更新与新学生移植，封存 per-round manifests、数据选择轨迹、成本与学习曲线。RoboCasa365 先以官方 GR00T checkpoint 重做 G0，若采用本地适配 WM 则重做 G1，再复验 G2 与 G4。
